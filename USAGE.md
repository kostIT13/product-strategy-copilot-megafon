# Как подключить Product Strategy Agent и работать с кейсом

Product Strategy Agent (PSA) — проект для работы руководителя цифрового продукта в Codex. **Codex ведёт диалог, PSA сохраняет кейс и проверяет материалы, руководитель выбирает вариант и подтверждает переходы.** Начните с CLI. FastMCP можно подключить, если хотите вызывать те же проверки из чата через MCP.

## 1. Откройте проект и установите зависимости

Нужны **Python 3.11 или новее**, **uv 0.11.30** и доступ к Codex для живого диалога. Установку зависимостей выполните заранее. Офлайн-прогон и проверки сохранённых материалов после установки обходятся без модели.

Если `uv` ещё не установлен, выберите способ установки для вашей системы и укажите версию 0.11.30. Затем переоткройте терминал, чтобы обновился путь к исполняемому файлу. [Установка uv](https://docs.astral.sh/uv/getting-started/installation/)

1. Распакуйте исходный ZIP или получите репозиторий. Откройте в Codex Desktop папку, где лежат `AGENTS.md`, `pyproject.toml`, `agent/` и `knowledge/`.
2. Запустите терминал в этой папке. Команды ниже показаны для PowerShell.
3. После проверки запуска начните новый чат в том же проекте.

```powershell
uv --version
uv sync --locked --no-default-groups --extra documents
uv run --no-sync psa doctor
uv run --no-sync python -m scripts.ci.demo
```

Дополнение `documents` нужно для PDF, DOCX и XLSX. Для базового CLI и двух офлайн-примеров можно запустить `uv sync --locked --no-default-groups`. Отчёт `doctor` должен показать готовность CLI. Предупреждение о недоступном FastMCP ожидаемо при установке без дополнения `mcp`. Успешный офлайн-прогон возвращает `ok: true`, два кейса и `model_calls: 0`.

> [!NOTE]
> Для основного маршрута достаточно доступа к Codex и локальной папки. Отдельный ключ API, `.env`, база данных и Docker не требуются. Конфигурации для других IDE есть в репозитории, живая приёмка проведена в Codex.

## 2. Попробуйте готовый кейс

Учебный кейс «Связь для близких» содержит вопрос вымышленного оператора, PDF-бриф, производную таблицу и сохранённую выдержку справки Pixel. Сборщик добавляет основания и варианты и оставляет кейс на этапе `intake`. Выбор в новой копии делает человек.

```powershell
$caseId = 'telecom-family-guide'
uv run --no-sync python examples/telecom-family/build_case.py --project-id $caseId
uv run --no-sync psa status $caseId
uv run --no-sync psa context $caseId
uv run --no-sync psa validate $caseId
uv run --no-sync psa verify $caseId
```

При повторе выберите новый ID. Сборщик защищает уже существующий кейс от перезаписи. Для отдельного каталога передайте `--projects-dir PATH` сборщику и всем командам PSA, а также укажите этот путь агенту.

В новом чате отправьте:

```text
Работаем с учебным кейсом telecom-family-guide по AGENTS.md.
Открой кейс через psa status, psa resume и psa context.
Покажи текущий этап, вопрос решения, три исходных материала с привязками
и главные неизвестные. Отдели условия учебного брифа от гипотез.
Проверь кейс через psa validate и psa verify. Остановись перед согласованием.
```

Ожидайте строку о загрузке инструкций с версией и хешем пакета, затем статус кейса и результат проверок. Для полного прохода используйте готовые реплики из гайда. Подставляйте ID своей копии и подтверждайте только те материалы, которые просмотрели.

## 3. Начните свой кейс

Назовите задачу, материалы и ожидаемый результат в первом сообщении:

```text
Создай кейс retention-study по AGENTS.md.
Задача: выяснить, на каком шаге регистрации пользователи чаще теряют прогресс,
и выбрать первое изменение для проверки. Результат нужен руководителю продукта.
Разрешённые входы: описанные мною локальные документы и таблицы.
Задай только вопросы, которые повлияют на следующий шаг. Зафиксируй бриф,
покажи ограничения и дождись моего согласования.
```

Если удобнее создать папку самому, один раз выполните `uv run --no-sync psa init retention-study`. Затем попросите агента открыть существующий кейс. Бриф, план исследования и авторские черновики находятся в каталоге кейса. Источники, реестры, состояние и сгенерированные отчёты меняются командами PSA.

Чтобы передать локальный материал, укажите путь к конкретному разрешённому файлу. Его можно зарегистрировать через терминал:

```powershell
uv run --no-sync psa source add retention-study '.\materials\brief.pdf' --title 'Бриф продукта'
uv run --no-sync psa source quality retention-study
uv run --no-sync psa verify retention-study
```

Замените путь на свой. Сохраняйте разрешённые оригиналы отдельно. PSA регистрирует извлечённый текст и его происхождение. Для PDF нужен текстовый слой. Например, для цитаты из PDF используется `page:N`, для текста и CSV — `paragraph:N`, для ячейки XLSX — `cell:'Лист'!B2`.

Для нового запроса к публичному сайту явно разрешите конкретный адрес или попросите использовать сохранённую копию. У каждого существенного факта нужна привязка к исходнику. Прогнозы, гипотезы и ответы модельных респондентов отмечаются отдельными типами.

## 4. Пройдите этапы и проверьте результат

| Этап | Что попросить и что проверить |
| --- | --- |
| Постановка и план | Покажи вопрос решения, критерий успеха, ограничения и вопросы исследования. Утвердите материалы нужного этапа. |
| Источники и основания | Покажи, откуда каждый важный вывод, где исходная цитата и какие сведения могут изменить выбор. |
| Варианты | Сравни минимум три направления, включая сохранение текущего положения и закрытие инициативы. Для каждого покажи издержки, риск и сильнейшее возражение. После чтения явно назовите выбранный ID. |
| Продуктовая и коммуникационная стратегии | Сверь цель, аудиторию, продуктовый сценарий, экономику, сообщение и подтверждение обещания. Подготовь актуальный пакет смысловой оценки. |
| План проверки | Покажи базу или способ её измерения, метрику с единицей и знаменателем, группу сравнения, окно, ответственного и защитные показатели. Подготовь отдельную оценку этого плана. |
| Завершение | Покажи итоговое решение, условия пересмотра и пути к двум стратегиям и плану проверки. |

Примеры реплик руководителя после просмотра:

- «От роли „Пользователь“ утверждаю показанный бриф кейса `retention-study` и разрешаю переход со стадии `intake)».
- «От роли „Пользователь“ утверждаю сравнение и выбираю O-003. Запиши мой выбор и покажи обе стратегии перед согласованием».
- «Принимаю все шесть критериев показанного актуального пакета стратегии и разрешаю переход со стадии `strategy`. Если снимок изменился, дождись моей повторной оценки».

Используйте реальные ID и названия этапов из статуса. Для стратегии и проверки эффекта смысловую оценку и разрешение на переход фиксируют отдельно для каждого актуального снимка. Шесть критериев охватывают основания, контекст, числа, альтернативы, обещания и неизвестные с условиями пересмотра. Запуск эксперимента, расходы и публикация требуют отдельного разрешения.

Перед передачей результата просите выполнить три проверки:

```powershell
uv run --no-sync psa validate retention-study
uv run --no-sync psa verify retention-study
uv run --no-sync psa coverage retention-study
```

`validate` проверяет структуру и связи, `verify` сверяет источники и цитаты, `coverage` проверяет, что существенные абзацы стратегий привязаны к основаниям или имеют маркировку неопределённости. Смысловую достаточность выводов оценивает человек.

Итоговые авторские материалы находятся в `projects/retention-study/drafts/`. Ищите `product-strategy.md`, `communication-strategy.md` и `validation-plan.md`. Если нужен обновлённый сводный комплект для чтения, попросите агента выполнить `psa render retention-study` и перечислить пути к собранным результатам.

## 5. Продолжите, остановите или пересмотрите работу

При переходе в новый чат откройте тот же проект и назовите ID кейса. Если кейс хранится отдельно, укажите его родительскую папку.

```text
Возобнови retention-study из сохранённой папки.
Вызови psa status, psa resume, psa context и psa decision summary.
Покажи этап, последнее решение, открытые вопросы и следующий шаг.
Не повторяй импорт или переходы. Если требуется согласование, дождись ответа.
```

| Что сказать | Действие агента |
| --- | --- |
| «Стоп. Покажи статус» | Остановит дальнейшие действия, покажет состояние и точку продолжения. |
| «Уточни задачу» | Сверит бриф и покажет, какие документы и согласования затрагивает изменение. |
| «Новый источник меняет вывод» | Покажет зависимые утверждения, варианты и решения. Исправление и переход выполняются после указания человека. |
| «Вернись на этап» | Покажет текущий снимок и условия возврата. После разрешения выполнит штатный откат или повторное открытие завершённого кейса. |

Для чтения контекста вне корня репозитория:

```powershell
uv run --project 'C:\work\psa' --no-sync psa context retention-study --projects-dir 'C:\work\cases' --instructions-root 'C:\work\psa'
```

Замените оба пути. Для диагностики незавершённой записи используйте `uv run --no-sync psa workflow pending retention-study`. Журнал показывает, какую операцию можно восстановить. Перед восстановлением сверяйте UUID и состояние.

## 6. Подключите FastMCP по желанию

Из корня установите оба дополнения и получите точные пути:

```powershell
uv sync --locked --no-default-groups --extra documents --extra mcp
uv run --no-sync python -c "import sys; print(sys.executable)"
(Get-Location).Path
```

Откройте или создайте локальный файл `.codex/config.toml`. Добавьте одну секцию `mcp_servers.psa`, сохранив остальные настройки. Замените значения `command` и `cwd` путями из предыдущего шага. После сохранения переоткройте проект и начните новый чат. Проект должен быть доверенным, чтобы Codex применил локальную конфигурацию.

```toml
[mcp_servers.psa]
command = 'C:\work\psa\.venv\Scripts\python.exe'
args = ["-m", "product_strategy_agent.mcp_server"]
cwd = 'C:\work\psa'
enabled = true
enabled_tools = ["psa_status", "psa_validate", "psa_verify", "psa_coverage"]
default_tools_approval_mode = "prompt"
```

Это подключение для чтения и проверок. В чате попросите вызвать четыре инструмента по именам на созданном кейсе, например `telecom-family-guide`. При отдельном каталоге передайте абсолютный `projects_dir`. Если сервер недоступен, используйте эквивалентные команды CLI. Для отключения можно установить `enabled = false` и переоткрыть проект.

Конфиг с путями оставляйте локально. Хуки и субагенты запускаются по отдельному запросу. Для субагента укажите роль, поручение и набор разрешённых материалов.

## 7. Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| `uv` не найден или версия отличается | Установите версию из `pyproject.toml`, переоткройте терминал и выполните `uv --version`. |
| `psa doctor` не запускается | Проверьте, что терминал открыт в корне, а `uv sync --locked` завершился. Вызовите `uv run --no-sync psa --help`. |
| Кейс отсутствует или выбран другой | Сверьте ID и родительский каталог. При нестандартном расположении добавьте `--projects-dir PATH`. |
| Контекст не загружается | Проверьте, что открыли корень с `AGENTS.md`. В другом каталоге укажите `--instructions-root`. |
| PDF без текста или XLSX не читается | Проверьте дополнение `documents`, формат и ограничения. Для скана подготовьте разрешённую текстовую выдержку с привязкой к оригиналу. |
| Согласование заблокировано | Прочитайте причину. Сверьте версию материалов, закройте замечания и запросите новый пакет, если снимок изменился. |
| MCP не виден в чате | Проверьте доверие проекту, пути в TOML и дополнение `mcp`. Переоткройте проект и проверьте в новом чате. |
