# Импорт локальных документов основной системы

> Историческая документация старого контура. PostgreSQL/Alembic/Docker и psa-main удалены 10.11.2026; эти команды больше не являются инструкцией запуска. Текущий путь — [README](../README.md), состояние переноса — [R2](legacy-retirement.md).

XLSX обрабатывается отдельным адаптером на [openpyxl](https://openpyxl.readthedocs.io/en/3.1/tutorial.html) из extra `documents`. Видимые листы выводятся в порядке книги; непустые ячейки сохраняются в виде `'Лист'!B2 [number] = 0.75`. Строковые значения экранируются как JSON; типы чисел, дат, boolean, ошибок и формул обозначены явно. Можно цитировать всю строку ячейки с locator `sheet:'Лист'!B2`. Автоматическая проверка соответствия locator адресу пока не выполняется; цитата проверяется по тексту ревизии.

Формулы сохраняются как `[formula]` с исходным выражением: они не вычисляются, кешированные результаты не используются. Внешние ссылки не загружаются. Скрытые/veryHidden-листы исключены и учитываются в limitations. Форматирование, диаграммы, изображения, комментарии и структура объединённых ячеек не извлекаются. Это текстовый импорт значений, без расчётной аналитики.

Лимиты XLSX: 20 листов, 10000 строк и 256 столбцов на лист, 100000 записанных ячеек суммарно (включая скрытые), 64 MiB распакованных частей, 2048 частей ZIP и 10 MiB выходного текста. Проверяются реальные XML-координаты; некорректный dimension не приводит к молчаливому усечению. Макросодержащие, зашифрованные, пустые и повреждённые книги отклоняются; `.xls`/`.xlsm` не поддерживаются. XML разбирается с defusedxml. Проверка: `docker compose --profile app run --build --rm app python scripts/smoke_xlsx.py`.

PDF читается отдельным адаптером на [pypdf](https://pypdf.readthedocs.io/en/latest/user/extract-text.html) из extra `documents`. В тексте сохраняются маркеры `[page:N]`, в реестре — диапазон `pages:1-N`; цитате можно указать locator `page:N`. Точность цитаты проверяется по тексту ревизии целиком; автоматическое доказательство соответствия указанному номеру страницы пока не реализовано. Название берётся из PDF metadata или имени файла.

PDF-парсер работает в strict-режиме: зашифрованные, повреждённые и полностью лишённые текстового слоя файлы отклоняются. OCR не выполняется. Страницы без извлечённого текста отмечаются в limitations. Порядок чтения, таблицы и расположение текста могут отличаться от визуального представления страницы.

Ограничения PDF: до 200 страниц, до 8 MiB декодированного content stream страницы и до 10 MiB результирующего текста. Проверка stream выполняется после декодирования; она не задаёт жёсткий предел памяти для декомпрессии. Изоляция процесса и тайм-ауты парсинга остаются задачей надёжности. Проверка PDF CLI на PostgreSQL: `docker compose --profile app run --build --rm app python scripts/smoke_pdf.py`.

```powershell
psa-main document import demo ./research.html --publisher "Организация"
psa-main document import demo ./notes.txt --encoding cp1251
```

Поддерживаются TXT, Markdown, CSV, JSON, HTML/HTM, DOCX, PDF и XLSX. Первые четыре формата читаются как текст; структурная аналитика CSV/JSON не выполняется. HTML разбивается на текстовые блоки, title сохраняется отдельно; script/style/noscript/svg/template исключаются. Сеть, JavaScript и связанные ресурсы не загружаются. По умолчанию используется UTF-8 с поддержкой BOM, другая кодировка задаётся явно. Ошибки декодирования не заменяются молча потерянными символами.

Размер входного файла ограничен 10 MiB; чтение ограничено лимитом плюс один байт. Пустые, неподдерживаемые и содержащие NUL документы отклоняются. OCR пока не поддерживается.

Для DOCX локально установите `python -m pip install -e ".[documents]"`; Docker-образ включает это extra. Адаптер использует [python-docx iter_inner_content](https://python-docx.readthedocs.io/en/develop/api/document.html#docx.document.Document.iter_inner_content), чтобы сохранить порядок абзацев и таблиц тела документа. Строки таблиц превращаются в текст с разделителем ` | `, название берётся из core properties или имени файла. Заголовки/колонтитулы, изображения, текстовые поля, вложенные таблицы и tracked changes полностью не извлекаются; объединённые ячейки могут повторяться. Эти ограничения сохраняются вместе с ревизией источника. Опция `--encoding` к DOCX не применяется.

DOCX ZIP-пакет проверяется до разбора: не более 2048 частей, суммарно не более 64 MiB распакованных данных; зашифрованные и повреждённые пакеты отклоняются. Размер grid span таблиц ограничен. Это ограничения входа, а не полная изоляция процесса парсера для production.

По умолчанию идентичность источника задаётся абсолютным file URI; `--uri` позволяет задать устойчивый исходный URL или иной идентификатор. `--title` и `--publisher` передают метаданные. Результат проходит через SourceService: сохраняются текст, его SHA-256, locator и ограничения извлечения. Повтор неизменённого текста идемпотентен, изменение создаёт ревизию. Оригинальный файл не архивируется, SHA-256 относится к извлечённому тексту.

При работе через Docker документ должен быть доступен внутри контейнера. Например, разрешённый материал из `projects/demo/research.html` импортируется командой `docker compose --profile app run --build --rm app psa-main document import demo /app/projects/demo/research.html`.

Проверки адаптера: `PYTHONPATH=src python -m unittest discover -s tests` (для PowerShell задайте `$env:PYTHONPATH='src'`). Интеграционный сценарий: `docker compose --profile app run --build --rm app python scripts/smoke_documents.py`. Он оставляет синтетический проект с уникальным ключом для аудита.
