# План до сдачи проекта

Актуально на 19.11.2026, исходный коммит `221cbc2`. Этот чек-лист задаёт порядок работы. Требования и критерии взяты из [ТЗ](../../specs/case.md). История реализации описана в [основном плане](plan-main.md), технические задачи расширенной автоматизации — в [плане готовности](production-readiness.md).

## Исходная точка

Файловый агент Codex с CLI, FastMCP, инструкциями, навыками и базой знаний реализован. Кейсы «Слот» и «Время выдачи» прошли полный учебный цикл с явным выбором и оценкой человека. Свежий чат Codex возобновил перенесённый кейс через CLI. Codex App Server подтвердил совпадение операций чтения, записи и пересмотра с CLI. Локальные хуки, пакеты для субагентов, восстановление файлового состояния и предварительная проверка записи эксперимента работают. «Слот» включён в ZIP. [Журнал разработки](../../reports/development-log.md), [приёмка FastMCP](../mcp-host-acceptance.md).

## 2. Подготовить и пройти демонстрационный проект — R3 / R4

19.11.2026 завершён первый проход кейса по примеру брифа. Сохранены решение O-003, обе стратегии, план проверки, единый документ из пяти частей и два воспроизводимых прогноза. На отдельной копии проверены возобновление и пересмотр после учебного обновления источника. Пользователь выбрал O-001, повторный проход завершён. Подробности и ограничения замеров в [журнале разработки](../../reports/development-log.md).

- [x] Добавить предоставленный командой [пример брифа](<../../specs/Пример брифа.pdf>) к материалам ТЗ. Тема — связь для близких и собственных устройств у вымышленного мобильного оператора. Числа из примера учебные.
- [ ] Подготовить демонстрационный кейс на основе примера. Сопоставить стандартные результаты агента с пятью частями брифа. В частности, отразить экономику и проверку пользы, прогноз в двух сценариях, план по кварталам, ориентир на конец третьего года, ресурсы и решения руководителя. Если организатор предоставит отдельный обязательный бриф, сверить с ним финальное демо. Сохранить отдельное свидетельство работы на другой задаче.
- [ ] Пройти путь от запроса до решения. Показать вопрос и план исследования, работу с документом, таблицей и сайтом, ссылки или локаторы, оценку источников, противоречия и пробелы. Подготовить статус-кво, прекращение и изменение с издержками, рисками и сильными возражениями. После выбора человека оформить обе стратегии и план проверки с метрикой, базой или способом её получить, сроком и защитными показателями.
- [x] Проверить паузу и продолжение, исправление результата и пересмотр после обновления источника. Сохранённые согласования и происхождение выводов читаются. Точный повтор импорта не создаёт второй ревизии.
- [ ] Для сравнения и отчёта записать полные замеры на отдельном сопоставимом прогоне. В уже завершённой репетиции измерены только отдельные локальные команды.
- [ ] Зафиксировать границу переносимости по §5. Текущий объём приёмки — Codex, инструкции для остальных IDE сохранены. Для буквального закрытия пункта требуется отдельный согласованный прогон в одной другой IDE. До такого прогона в материалах указывать подтверждённый перенос папки и свежий чат Codex.

**Готово, когда** результат воспроизводится по инструкции и лежит в читаемых артефактах. В матрице ТЗ есть указание на подтверждённые сценарии и открытый пункт переносимости, если объём проверки остаётся прежним.

## 3. Доказать пользу основного процесса — R5 / M6

- [ ] Зафиксировать фактическую модель, настройки и лимиты перед запуском. Оба условия используют один PDF и один запрос по [протоколу M6](../evaluation/telecom-m6.md). Для обычного чата использовать свежий контекст без ранее созданных материалов кейса.
- [ ] Зафиксировать качество оснований и стратегий, время модели и человека, расходы на модели, поиск и инструменты, повторы, ожидание, ошибки и доработку. Неизвестные значения оставить неизвестными. Обоснованные оценки обозначить отдельно от замеров.
- [ ] Получить независимую оценку результатов с нейтральными метками и примерами по рубрике. Записать различия, ограничения и случаи, где агент требует дополнительной помощи. [Протокол оценки](../evaluation/README.md).

**Готово, когда** есть два результата, независимая оценка и прозрачная таблица затрат и качества. Этот прогон можно готовить параллельно с демо.

## 4. Завершить выбранные сценарии расширенной автоматизации — P4–P8

- [ ] Проверить в Codex один сценарий с субагентом и один сценарий с хуком. Зафиксировать правила включения, проверку лимитов, остановку и восстановление, результат при ошибке и последовательный путь. Проверить, что решения и переходы по-прежнему подтверждает человек.
- [ ] Сравнить последовательный прогон с прогоном с автоматизацией в одинаковых условиях по протоколу P8. Принимать компоненты в поддерживаемый сценарий по результатам замеров качества, скорости, стоимости или удобства сопровождения. Для остальных возможностей указать подтверждённые ограничения. Поиск и маршрутизацию расширять при подтверждённом пробеле и измеримой пользе. [Парная оценка](../evaluation/paired-ide-preparation.md).

**Готово, когда** у каждой заявленной возможности есть проверенный сценарий и записанное решение об объёме поддержки. Работу над базовой приёмкой, демо и сравнением с обычным чатом можно вести до завершения P8.
