# Резервное копирование development-БД

> Историческая документация старого контура. PostgreSQL/Alembic/Docker и psa-main удалены 10.11.2026; эти команды больше не являются инструкцией запуска. Текущий путь — [README](../README.md), состояние переноса — [R2](legacy-retirement.md).

Команды выполняются Python 3.11+ на хосте из репозитория. Docker Desktop и Compose-сервис `postgres` должны быть запущены. Учётные данные берутся из окружения контейнера; секреты не передаются аргументами команд.

```powershell
python scripts/postgres_backup.py backup
python scripts/postgres_backup.py restore backups/ИМЯ.dump --database restored_dev
```

Backup использует `pg_dump --format=custom` внутри PostgreSQL-контейнера. Архив копируется через `docker compose cp`, поэтому двоичные данные не проходят через текстовый pipeline PowerShell. Рядом сохраняется `.dump.json` с SHA-256. Каталог `backups/` исключён из Git и Docker build context. Архивы вне этого каталога нужно хранить самостоятельно как данные проекта.

Restore принимает архив и его манифест, проверяет SHA-256 и создаёт новую БД через `createdb`. Если имя уже занято, операция завершается ошибкой. `pg_restore` работает одной транзакцией с `--exit-on-error --no-owner --no-acl`. При ошибке восстановления новая БД может остаться пустой; исходная БД не изменяется. Пользователи, роли и права доступа не переносятся.

Это ручной backup/restore для локальной разработки. Расписание, шифрование, политика хранения и удалённая копия ещё не добавлены. Проверку восстановления следует повторять после существенных изменений схемы. SHA-256 обнаруживает повреждение архива, но не подтверждает доверенность его автора.
