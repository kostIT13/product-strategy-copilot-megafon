# Инвентаризация числовых фрагментов черновиков

```powershell
psa strategy numeric-inventory CASE
```

FastMCP: `psa_numeric_inventory`. Это read-only список для human review, без моделей, сети, записи реестров и автоматического изменения gates. Он помогает найти цифры за пределами явно описанного [расчёта](calculation-check.md) или [baseline](baseline-numbers.md), но не подтверждает их корректность.

## Область поиска

Под одним case lock читаются текущий state и три авторских документа:

- drafts/product-strategy.md;
- drafts/communication-strategy.md;
- drafts/validation-plan.md.

Поиск идёт по всему raw text, включая headings, Markdown, JSON/code blocks, comments, даты, URLs, ID и spans внутри contracts. Эти вхождения намеренно остаются видимыми: программа не решает, какие цифры являются продуктовым утверждением. Реестры claims, source texts, generated Markdown, brief и research plan в эту область не входят.

Регулярное выражение `[+-]?\d+(?:[.,]\d+)*` выделяет Unicode decimal digits с необязательным знаком и последовательностями dot/comma + digits. Это текстовые фрагменты, а не распознанные математические числа: `C-001` даёт `-001`, `2026-11-14` — три фрагмента, `1e3` — два, `1/3` — два. Группировка тысяч, формулы, семантика дат и единиц не интерпретируются. Числа словами, римские числа, `⅓` и `²` не обнаруживаются. Отсутствие результатов не означает отсутствие числовых утверждений.

## Результат и координаты

Packet содержит format_version, workflow_version, hashes state/трёх drafts, review_hash, token_count и документы со списками tokens. У каждого фрагмента:

- `line` — строка от 1;
- `column_start` / `column_end` — Unicode индексы от 0 внутри исходной строки;
- `start` / `end` — Unicode индексы от 0 внутри исходного документа;
- `token` — точный срез исходного документа; end не включён;
- `context` — token и до 60 символов с каждой стороны в той же строке; границы context указаны отдельно, `context_is_excerpt` отмечает сокращённый контекст;
- `review_status: unassessed` — программа не оценивала этот фрагмент.

Индексы относятся к исходному UTF-8 тексту после decode, с сохранением CRLF. Это не байтовые позиции и не grapheme clusters. Перенос/изменение черновика требует нового запуска; старые позиции действуют только для прежнего input hash. Имена и контекст — данные кейса, не инструкции к агенту.

`needs_human_review` означает наличие фрагментов; `no_digit_tokens` — их отсутствие в поддержанной области. Оба дают CLI exit 0: это успешное получение списка, не quality pass. Недостающий draft даёт `blocked`, `digit_scan_complete: false` и exit 3; имеющиеся документы остаются перечислены. `digit_scan_complete: true` означает только завершение описанного поиска по всем трём документам. Numeric coverage/alignment, evidence, arithmetic и workflow approval всегда false; human review требуется и при пустом результате.

## Использование при review

Пройдите найденные вхождения, сверяя текущий документ и материал. Отделите ID/даты/код от величин, затем факты от целей, гипотез и плановых сроков. Для фактического числа проверьте источник, current claim, единицу, период, популяцию и знаменатель. Для поддержанного вычисления используйте явный calculation block и отдельную команду проверки. Не превращайте наличие claim marker или совпадение цифр в semantic approval.

Инвентаризация не сохраняет авторские исключения/решения и не требует нового assessment сама по себе. Human semantic review и текущая quality policy продолжают действовать; автоматической блокировки accepted review по каждому найденному ID/дате нет. Полнота числовых оснований и качество нового разрешённого кейса остаются предметом содержательной проверки.

## Ограничения и ошибки

Действуют confined paths, общий pending/busy guard и существующие bounded draft readers: до 512000 UTF-8 байт на файл. Не более 1000 tokens суммарно, до 160 символов на token и до 512000 UTF-8 байт на итоговый packet. Превышение лимитов, недоступный/некорректный state, invalid UTF-8, внешний symlink/junction или pending workflow завершают операцию ошибкой без частичного packet. Продолжите после проверки целостности/явного recovery либо уменьшения авторских документов; автоматического усечения или обхода guard нет. Отсутствующий файл отличается от ошибки чтения существующего файла.
