# Проверка сравнения альтернатив

Запишите минимум три варианта. Рассмотрите сохранение текущего положения (`status_quo`), закрытие направления (`stop`) и изменение (`change`). Для каждого опишите механизм, ожидаемую пользу, издержки, риски и сильнейшее возражение. Указывайте основания через `--claim`, ключевые допущения через `--assumption` и способы проверки в авторских заметках или реестре пробелов. Если оценка неизвестна, объясните причину и способ её уточнения.

Выполните `psa option check ID` или вызовите MCP `psa_option_check`. Результат показывает версию кейса, недостающие роли и для каждого варианта перечисляет незаполненные поля и отмечает затронутые основания. Одиночные заглушки вроде TODO и «неизвестно» считаются пустыми. `ready` требует хотя бы по одному заполненному варианту каждой роли с актуальными основаниями, если они указаны.

`psa gate approve ID --stage options` проверяет те же условия. Чтобы дополнить старый неполный вариант, запишите полную версию через `psa option add`, затем используйте её новый ID в сравнении и при записи человеческого выбора. Старая запись видна в отчёте как неполная. История ранее пройденных этапов доступна через журнал. Содержательную различимость, качество аргументов и силу возражений оценивает человек по материалам сравнения.
