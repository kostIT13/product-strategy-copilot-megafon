# Запуск агента в Codex и сценарий демо

В демонстрации руководитель вымышленного оператора выбирает, какую помощь со связью проверить первой. Доступны семейное предупреждение, напоминание владельцу нескольких номеров, сохранение обслуживания и закрытие инициативы. Используйте учебный [пример брифа](<../specs/Пример брифа.pdf>). Если организатор выдаст отдельный обязательный бриф, согласуйте с ним итоговое демо. [Требования к видео](../specs/case.md#11-материалы-для-сдачи).

## 1. Подключите проект и проверьте запуск

1. Откройте **корень репозитория** в Codex Desktop как локальный проект. В корне должны быть `AGENTS.md`, `pyproject.toml`, `agent/`, `knowledge/` и `examples/`. Запустите новый чат в этом проекте. Codex ведёт диалог и получает инструкции из `AGENTS.md`. PSA ведёт состояние и проверки на диске. [Инструкции проекта](../AGENTS.md) · [инструкции Codex](https://developers.openai.com/cookbook/examples/codex/iterating-development-workflows-with-codex).
2. В PowerShell из корня выполните команды ниже. Нужны Python 3.11+ и uv 0.11.30. Для основного пути используйте действующий вход в Codex. Отдельные API-ключи и `.env` не требуются.

```powershell
uv --version
uv sync --locked --no-default-groups --extra documents
uv run --no-sync psa doctor
uv run --no-sync python -m scripts.ci.demo
uv run --no-sync python examples/telecom-family/build_case.py
uv run --no-sync psa status telecom-family-demo
uv run --no-sync psa validate telecom-family-demo
uv run --no-sync psa verify telecom-family-demo
uv run --no-sync psa coverage telecom-family-demo
```

`doctor` должен показать готовность CLI. Без FastMCP предупреждение об этом extra ожидаемо. `scripts.ci.demo` прогоняет два отдельных офлайн-примера. Для телеком-кейса ожидаются `intake`, три источника, девять цитат, четыре варианта и 11 проверенных абзацев. Стратегии в сборке — заранее подготовленные условные черновики для O-003. В записи покажите фактическое решение и то, как Codex проверяет или уточняет эти черновики. [Сборщик и исходные материалы](../examples/telecom-family/README.md).

Сборщик отказывается перезаписывать существующий ID. Для новой репетиции используйте `--projects-dir .venv-ci/demo-take-02` при сборке, добавьте тот же `--projects-dir` к командам PSA и укажите его в каждом запросе в Codex. Если используете MCP, передавайте также `projects_dir` с абсолютным путём к этой папке.

### Опционально подключите FastMCP

Для записи достаточно основного пути через CLI. Если хотите показать MCP, установите extra и получите абсолютный путь к Python текущего проекта:

```powershell
uv sync --locked --no-default-groups --extra documents --extra mcp
uv run --no-sync python -c "import sys; print(sys.executable)"
```

В локальной `.codex/config.toml` добавьте или обновите **одну** секцию `mcp_servers.psa`. Сохраните существующие настройки. Подставьте свои абсолютные пути. Codex загружает настройки проекта после доверия к проекту. После изменения переоткройте локальный проект и начните новый чат. [Поля настройки MCP в Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) · [проверка FastMCP в Codex](mcp-host-acceptance.md).

```toml
[mcp_servers.psa]
command = 'C:\Users\Yaroslav\Desktop\mgimo\.venv\Scripts\python.exe'
args = ["-m", "product_strategy_agent.mcp_server"]
cwd = 'C:\Users\Yaroslav\Desktop\mgimo'
enabled = true
enabled_tools = ["psa_status", "psa_validate", "psa_verify", "psa_coverage"]
default_tools_approval_mode = "prompt"
```

Оставьте этот конфиг локальным. Он исключён из Git. Codex запускает сервер сам. Если инструменты не появились, проверьте пути, наличие extra и статус локального проекта. Для отключения установите `enabled = false` и переоткройте проект. Продолжить работу можно через те же команды CLI.

**Запрос для проверки MCP**

```text
Для учебного кейса telecom-family-demo вызови напрямую четыре MCP-инструмента сервера psa: psa_status, psa_validate, psa_verify и psa_coverage. Покажи этап, статус проверок, ошибки, предупреждения и количество проверенных абзацев. Ничего не меняй. Если MCP недоступен, скажи об этом и выполни те же проверки через PSA CLI.
```

## 2. Запишите сквозной сценарий

Подготовку зависимостей проведите заранее. Сохраните реальные реплики и результаты, вырежьте только ожидание. Подойдёт ориентир **9 минут 30 секунд**. Показывайте заголовки и ключевые фрагменты вместо длинного вывода. Для сдачи зафиксируйте время записи и ручного участия. Токены или расходы оставляйте неизвестными, если Codex их не показывает.

| Время в ролике | Что показать |
| --- | --- |
| 0:00–0:45 | Задача руководителя, корень проекта и проверка подключения |
| 0:45–2:30 | PDF, CSV и выдержка сайта с одним локатором на источник |
| 2:30–4:10 | Четыре варианта и явная реплика выбора человека |
| 4:10–6:25 | Обе стратегии, прогноз и смысловая оценка |
| 6:25–8:20 | План проверки и продолжение из нового чата |
| 8:20–9:30 | Сохранённое решение, ограничения и один итоговый кадр с артефактами |

### Запрос 1. Старт и доказательства

В первом чате отправьте:

```text
Ты помогаешь руководителю вымышленного мобильного оператора. Работаем в учебном кейсе telecom-family-demo по AGENTS.md. Помоги решить, какое небольшое изменение стоит проверять первым, чтобы клиенты могли вовремя отреагировать на риск перебоя связи.

Открой текущий кейс через psa status, resume и context. Покажи вопрос решения, план исследования и три импортированных материала. Приведи по одному утверждению с ID источника, точной привязкой и кратким выводом из PDF, CSV и выдержки Pixel Phone Help. Раздели условия брифа, гипотезы и неизвестные. Объясни, почему CSV производен от PDF, а справка Pixel подтверждает доступность уведомления на устройстве, но не эффект семейного сигнала. Используй сохранённые материалы. Запусти source quality, validate и verify, покажи предупреждения. Остановись перед согласованиями.
```

**В кадре** откройте `03_evidence.md`. Покажите C-002 со страницей 3 PDF, C-008 с `paragraph:2` CSV и C-009 с локатором сохранённой выдержки. Затем перейдите к вариантам.

### Запрос 2. Согласование подготовительных этапов и сравнение

Отправьте после проверки брифа, плана, источников и оснований:

```text
От роли «Пользователь» утверждаю бриф, план исследования, сбор источников и обзор доказательств кейса telecom-family-demo. Разрешаю провести четыре соответствующих перехода по порядку: intake, research_plan, source_collection, evidence_review. При блокере остановись и покажи его.

На этапе options покажи все четыре варианта. Для каждого назови пользу, издержки, риск, сильнейшее возражение и условие пересмотра. Выполни option check и дождись моего выбора.
```

**В кадре** покажите `04_options.md` или `analysis/options-comparison.md`. Отдельно объясните разницу между сохранением текущего обслуживания и закрытием нового направления.

### Запрос 3. Выбор человека и подготовка стратегии

Демонстрационный выбор O-003 соответствует условным черновикам. Если действительно согласны с этим вариантом, отправьте:

```text
От роли «Пользователь» утверждаю сравнение и разрешаю переход со стадии options в кейсе telecom-family-demo. Выбираю O-003 — исследовать семейное предупреждение о низком остатке со ссылкой на существующее ручное выделение интернета на одном совместимом тарифе. Запиши мой выбор штатной командой PSA. Это решение о предпроектной проверке.

Сверь и при необходимости уточни продуктовую и коммуникационную стратегии по этому выбору. Покажи, кто получит уведомление, при каких правах и как виден результат операции. Пересчитай два сценария по пяти показателям из CSV. Покажи неизвестные для решения о пилоте, затем выполни render, validate, verify, coverage, strategy check и review prepare для strategy. Покажи блокировки, шесть пунктов оценки, версию и review hash. Остановись перед strategy gate.
```

**В кадре** откройте обе стратегии в `drafts/` и сводный прогноз. При исходных допущениях пример даёт 279,25 и 278,65 млн ₽ валовой прибыли при цели 285 млн ₽. Это условный пересчёт, эффект ещё предстоит измерить.

### Запрос 4. Принятие стратегии и подготовка плана проверки

Перед принятием проверьте шесть пунктов: основания, популяцию/период/условия, числа/единицы/знаменатели, альтернативы, продуктовые ограничения и условия пересмотра. Только если все шесть действительно приняты и пакет актуален, отправьте:

```text
От роли «Пользователь» принимаю все шесть критериев актуальной стратегии O-003 в кейсе telecom-family-demo. Разрешаю записать мою оценку для показанного hash и выполнить strategy gate с её UUID. Если снимок изменился или есть блокеры, покажи актуальный пакет и дождись моего ответа.

На validation покажи отдельный план проверки: метрику, неизвестную базу и способ её получить, контроль, окно наблюдения, ответственного, защитные сигналы и правило остановки. Проверь структуру плана и подготовь отдельный review prepare для validation. Остановись перед новым согласованием.
```

**В кадре** откройте `drafts/validation-plan.md`. Покажите базу как неизвестную, сравнение на уровне семейных групп и семидневное окно измерения ограничения. Сохраните этот момент перед финальным согласованием.

### Запрос 5. Возобновление в новом чате

Перейдите в **новый чат того же локального проекта**. Предыдущие ответы туда копировать не нужно. Отправьте:

```text
Возобнови учебный кейс telecom-family-demo из сохранённой папки. Выполни psa status, psa resume, psa context и psa decision summary. Покажи текущий этап, последнее решение с ID варианта и следующий шаг. Назови документы, из которых это восстановлено. Выполни validate и verify. Не повторяй импорт, выбор или переходы и не меняй материалы. Если следующий шаг требует оценки человека, покажи текущий validation review для него.
```

**В кадре** покажите новый чат, сохранённый `D-001 / O-003`, этап `validation` и следующий шаг. Если есть сохранённая исходная репетиция, обозначьте её как исторический пример и показывайте только чтение.

### Запрос 6. Завершение учебного workflow

Отправьте только после отдельной проверки всех шести критериев актуального плана:

```text
От роли «Пользователь» принимаю все шесть критериев актуального плана проверки O-003 для telecom-family-demo. Разрешаю записать мою оценку для показанного hash и выполнить validation gate с её UUID. При отличии версии или наличии блокера остановись.

Покажи статус, решение и условие пересмотра, дай ссылки на две стратегии и план проверки. Выполни validate, verify и coverage и сообщи, что осталось неизвестным. Разрешение относится только к учебному переходу.
```

**В кадре** ожидается `completed` после успешного перехода. Покажите, что решения о фактическом пилоте, бюджете и публикации потребовали бы отдельного разрешения.

## 3. Если есть время в ролике

Для демонстрации пересмотра используйте готовую историческую копию телеком-кейса и озвучьте, что действие уже произошло в отдельной репетиции. Запрос для имеющейся копии:

```text
Только прочитай локальную копию telecom-family-connectivity в каталоге .venv-ci/telecom-revisit-8bpe4cy5. Покажи через status, decision summary, revisit list и revisit context SRC-REV-0001, какие утверждения и решения затронула учебная ревизия. Покажи исходные 500 ₽, исправленные 400 ₽, историю выбора и текущий O-001. Ничего не меняй.
```

Этот каталог существует только в исходном рабочем окружении. Из распакованного ZIP используйте [воспроизводимый пример пересмотра](demo-runbook.md) как отдельный учебный сюжет или покажите [отчёт репетиции](../reports/2026-11-21-telecom-demo-rehearsal.md). Для кадра о другой задаче предусмотрен [пример «Слот»](../examples/slot-workshop/README.md).

Если встречается предупреждение о локаторе, откройте извлечённый текст и проверьте точный синтаксис. Для PDF используется `page:N`, для текста, CSV и сохранённой HTML-выдержки — `paragraph:N` по непустым строкам. При блокере смысловой оценки покажите сообщение и исправьте причину штатной операцией на учебной копии. Для записи используйте только разрешённое учебное окружение, скройте учётные данные и посторонние окна.
