# Модельный респондент в IDE

Используйте вымышленную роль, чтобы найти гипотезы и вопросы для реального исследования. Подготовьте JSON с вопросом решения, ролью, ситуацией, допущениями и одним–восемью вопросами:

```json
{
  "decision_question": "Стоит ли упрощать перенос записи?",
  "fictional_role": "Вымышленный пользователь, впервые переносящий запись",
  "situation": "Нужно выбрать новое время в течение короткого перерыва.",
  "assumptions": ["Пользователь ещё не знаком с этим процессом."],
  "questions": ["С чего вы бы начали?", "На каком шаге вы могли бы отказаться?"]
}
```

Выполните `psa interview prepare-respondent --input brief.json` или вызовите `psa_prepare_respondent(brief=...)`. Передайте полученный пакет модели в открытой IDE, когда пользователь явно выбрал модельное интервью. Прочитайте вопросы по порядку. Пусть модель отвечает в вымышленной роли, обозначает допущения и неопределённость. После диалога попросите её выйти из роли и сформулировать проверяемые гипотезы.

Сохраните JSON в следующем формате. В `brief` вложите весь исходный бриф. В `result.brief_sha256` скопируйте хеш из результата подготовки. Ответы должны идти в порядке вопросов. Пример объекта `result`:

```json
{
  "brief_sha256": "<хеш из пакета>",
  "responses": [
    {"question_number": 1, "answer": "Наверное, сначала я бы проверил доступные даты."},
    {"question_number": 2, "answer": "Я мог бы уйти, если бы новое время было скрыто до подтверждения."}
  ],
  "hypotheses": [
    {
      "statement": "Видимость нового времени может снизить неопределённость.",
      "question_numbers": [2],
      "real_world_check": "Провести согласованную проверку понятности экрана переноса.",
      "disconfirming_observation": "Участники одинаково хорошо находят новое время в обоих вариантах."
    }
  ]
}
```

Выполните `psa interview export-respondent --input capture.json` или вызовите `psa_export_respondent(capture=...)`. Команда проверит хеш, номера вопросов и наличие плана проверки каждой гипотезы. Она вернёт JSON с полями `transcript` и `hypotheses`. Сохраните текст `transcript` отдельным TXT без редактирования заголовка, если нужны цитаты и тематический разбор. Импортируйте его по явной задаче и используйте [разбор интервью](interview-analysis.md) с `material_kind: synthetic_dialogues`. Сохраняйте выводы такого сценария с типом `synthetic`, а вопросы для реальной проверки — в реестре пробелов.

Результат имеет область `hypothesis_only`. Доля участников, размер спроса и готовность платить требуют самостоятельных оснований. Команды работают локально с переданным JSON. Сам диалог ведёт выбранная IDE, поэтому технические тесты проверяют подготовку, передачу и разбор результата на синтетических данных.
