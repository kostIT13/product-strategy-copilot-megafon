# P5b: ограниченный обход и пути файловых журналов

Срез hardening от 16.11.2026. Дополняет [P5a config integrity](host-config-integrity.md). Схемы записей, команды, human gates и native activation не меняются.

## Закрытый сценарий

Раньше stores выполняли `list(folder.iterdir())` и только затем проверяли размер истории. Лимит не ограничивал исходный обход/выделение памяти. Кроме того, pending-инспекция файловых журналов могла пропускать запись с final-looking именем до проверки её пути, включая ссылку.

Общий persistence helper использует контекстный `os.scandir`: собирает максимум разрешённое число путей, при первой лишней записи возвращает ошибку и закрывает iterator. Не выдаёт первые 1000 записей как полный результат. До добавления и до исключения служебного имени проверяет confinement; symlinks/junctions внутри и вне выбранного корня отклоняются. Вложенные каталоги рекурсивно не обходятся, содержимое записей читают прежние bounded decoders.

| Журнал | Область ограничения |
|---|---|
| Subagent tasks/results/reviews | До1000 directory entries на каждый kind; до1000 pending rows суммарно, как прежде |
| Hook runs | До1000 operation directories |
| Host observations и наследуемые reviews | До1000 entries на канал |
| Config operations | До1000 операций; единственный ACTIVE.json исключается из счётчика после проверки пути |
| Config operation audit | До5 известных entries на operation; неизвестные entries дают issue либо отказ по лимиту |
| Interrupted staging archive | До16 snapshots; перед созданием нового допускается не более15 существующих |

Перед новой публикацией допускается максимум999 текущих entries: место для новой записи учитывается заранее. Existing replay и прочитанные receipts не превращаются в новые записи. История не очищается автоматически. Пути, число записей и файлы проверяются под прежними участвующими OS locks.

## Проверки и работа с отказом

Проверены ранний отказ на управляемом iterator из миллиона потенциальных entries, закрытие iterator при успехе/ошибке, точный предел1000 и учёт ACTIVE. Проверены все пять pending adapters, включая наследуемый host review. На Windows созданы реальные junctions с final-looking именами на внешний каталог и служебным ACTIVE именем на внутренний; содержимое внешнего sentinel не читалось адаптером и не менялось. На POSIX этот тест использует symlinks; в этой итерации выполнялся Windows-прогон.

При переполнении не удалять записи ради успешной проверки. Сохранить согласованную приватную копию и разобрать историю отдельно. Не заменять неизвестный/повреждённый журнал пустым. Config recovery и audit описаны в [runbook P5a](host-config-integrity.md). Не запускать recover при одном лишь превышении лимита: он не является очисткой или общей миграцией.

## Границы

Это ограничение числа entries, которые код сохраняет/проверяет, а не обещание жёсткого wall-clock timeout файловой системы. Не заявляется транзакция с внешним редактором, защита от конкурентной подмены пути вне participating lock, OS sandbox или обнаружение hardlinks. Полный аудит содержимого всех final records этим изменением не добавлен: pending продолжает отвечать на вопрос о незавершённых публикациях.
