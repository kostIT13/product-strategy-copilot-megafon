# Полнотекстовый поиск источников

Примените миграции (`alembic upgrade head` или Compose migrate с `--build`). Миграция 0008 добавляет generated tsvector и GIN-индекс; старые ревизии также получают вычисленный вектор. Индекс содержит название с весом A и первые 100000 символов извлечённого текста с весом B. Ограничение объёма защищает от превышения размера tsvector; для полного поиска в больших документах потребуется индексация фрагментов.

```powershell
psa-main search demo "удержание клиентов"
psa-main search demo '"customer retention"' --limit 5 --json
```

Используется PostgreSQL `websearch_to_tsquery` с явной конфигурацией `pg_catalog.simple`: регистр нормализуется, морфологического стемминга и семантического поиска нет. Поддерживается синтаксис websearch PostgreSQL, включая фразы в кавычках. Запрос ограничен 1000 символами, число результатов — от 1 до 50.

Результаты принадлежат только запрошенному проекту и только последней ревизии каждого источника. Старые ревизии сохраняются для цитат, но их текст не участвует в выдаче. Возвращаются source/revision UUID, номер ревизии, URI, SHA-256, locator, score и excerpt. Score показывает лексическую релевантность, а не достоверность. Excerpt — подсказка для чтения с маркерами `[[...]]`, не готовая подтверждённая цитата; проверяйте исходный текст ревизии через ClaimService. Excerpt остаётся недоверенным текстом, его следует экранировать при отображении в HTML.

Проверка на PostgreSQL: `docker compose --profile app run --build --rm app python scripts/smoke_search.py`. Сценарий создаёт синтетические проекты, проверяет веса title/body, фразы, кириллицу, изоляцию проектов, исключение старых ревизий и CLI JSON. Индексация использует [generated column и GIN по документации PostgreSQL](https://www.postgresql.org/docs/17/textsearch-tables.html).
